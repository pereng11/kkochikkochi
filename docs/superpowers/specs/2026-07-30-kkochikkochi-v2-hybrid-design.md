# KkochiKkochi v2 — 하이브리드 게이트 설계

작성일: 2026-07-30
대체 대상: `2026-07-29-kkochikkochi-design.md` §4, §6, §9 (나머지 절은 유효)

## 1. 왜 바꾸는가

v1은 Claude Code의 `PreToolUse` 훅에서 **bash 명령 문자열을 파싱해** 그것이 `git commit`인지, 무엇이 커밋될지를 알아내려 했다. 구현과 세 차례의 수정 웨이브에서 나온 결함이 거의 전부 이 한 곳에서 나왔다.

| 결함 | 증상 |
|---|---|
| C1 | 인용된 메시지 안의 `--` → 게이트 무력화 |
| C2 | 맨 pathspec → 누락 포함 |
| B1 | `--pathspec-from-file` → 해당 파일들 미검증 통과 |
| 개행 | `echo hi⏎git commit -m x` → 통과 |
| N1 | 마커 계산 O(n²) → 타임아웃 → fail-open 통과 |
| — | 토크나이저 O(n²), 청크 경계, `'\''` 이스케이프, `-C` 대상 저장소 |

세 웨이브 모두 목표는 정확히 닫았고, 세 번 모두 같은 부류를 새로 열었다. **결함이 아니라 접근이 문제다** — 임의의 bash 명령을 셸에서 정확히 파싱하는 것은 이 도구가 감당할 난이도가 아니다.

## 2. 핵심 발견

git이 직접 호출하는 `pre-commit` 훅은 **커밋될 내용을 정확히 본다.** 측정 결과:

| 명령 | 훅 실행 | 훅의 `git diff --cached` | v1 설계가 원한 정책 | 일치 |
|---|---|---|---|---|
| `git commit` | ✅ | 정확 | 게이트 | ✓ |
| `git commit -a` | ✅ | 워크트리 반영해 정확 | 게이트 | ✓ |
| `git commit -- <path>` | ✅ | 정확 | 게이트 | ✓ |
| `--pathspec-from-file` | ✅ | 정확 | 게이트 | ✓ |
| `--amend` | ✅ | 델타만 | 게이트 (D12) | ✓ |
| `revert` | ❌ | — | 통과 (D13) | ✓ |
| `cherry-pick` | ❌ | — | 통과 (D13) | ✓ |
| `merge` | ❌ | — | 통과 (D13) | ✓ |
| `--no-verify` | ❌ | — | — | ⚠ |

**v1이 코드로 구현하려던 트리거 정책 전부가 git 자체 동작에서 공짜로 나온다.** D12와 D13은 이제 구현 대상이 아니라 관찰된 사실이다.

## 3. 아키텍처

두 훅이 서로 다른 일을 한다. **게이트는 git 훅이고, Claude 훅은 게이트가 존재하도록 보장하는 장치다.**

```
git commit
   │
   ├─ [1] Claude PreToolUse 훅  ── 전역. 설치 불필요. 안전 경로 아님
   │        · 이 저장소에 우리 pre-commit 훅이 설치돼 있는가?  (파일 존재 확인)
   │            없음 → deny + 에이전트가 그대로 실행할 설치 명령을 제시
   │        · --no-verify 가 보이는가?  (단순 문자열 확인)
   │            보임 → deny
   │
   └─ [2] git pre-commit 훅  ────── 진짜 게이트. 놓칠 수 없음
            · git diff --cached --raw  ← 이것이 곧 커밋될 내용. 파싱 없음
            · covered.tsv 와 대조 → 미검증이면 exit 1
            · 기존 훅이 있으면 먼저 실행하고 그 결과를 존중
```

### 3.1 리스크 방향의 반전

v1에서 파싱 버그는 **게이트 우회**였다. v2에서 파싱 버그는 **안내를 한 번 못 띄우는 것**이다. Claude 훅이 명령을 놓쳐도 git 훅이 그대로 막는다.

이것이 v2를 채택하는 가장 큰 이유다. 안전이 정확한 파싱에 의존하지 않는다.

### 3.2 삭제되는 것

- `scripts/lib-tokenize.sh` — 전체
- `scripts/pending-set.sh` — 인자 파싱 전부. 인자 없는 스크립트가 된다
- `hooks/gate.sh` — 토크나이저, `git commit` 매처, 충돌 방지 마커 계산, `-C` 해석
- `skills/kkochikkochi/SKILL.md` — `<BLOCKED_COMMAND>` 전달과 `'\''` 이스케이프 규칙 전체
- `tests/command-forms.bats` — 명령 형태 행렬. 검증 대상이 사라졌다

## 4. git pre-commit 훅

```sh
# hooks/pre-commit (설치 시 저장소로 복사됨)
1. 체이닝: 기존 훅이 보존돼 있으면 먼저 실행. 0이 아니면 그 코드로 즉시 종료
2. git diff --cached --raw --abbrev=40 --no-renames  → (SHA, 경로) 집합
3. 비어 있으면 exit 0
4. covered.tsv 와 대조. 전부 커버되면 exit 0
5. 미커버가 있으면 stderr 에 안내를 쓰고 exit 1
```

**fail-open은 여기서 뒤집힌다.** v1의 fail-open은 "게이트 버그가 커밋을 영구 차단하면 안 된다"였고, 그 위험은 파싱 실패에서 왔다. v2의 게이트는 `git diff --cached` 한 줄이라 실패할 지점이 사실상 없다. 그럼에도 다음은 통과시킨다: `jq` 부재, `covered.tsv` 손상, 상태 디렉터리 접근 불가. 이해 검증 이외의 이유로 커밋을 막지 않는다.

### 4.1 stderr 가 곧 인터페이스

git이 exit 1을 받으면 커밋을 중단하고, 훅의 stderr는 Bash 도구 출력으로 에이전트에게 그대로 간다. 별도 채널이 필요 없다. 메시지는 에이전트가 읽고 바로 행동할 수 있는 형태로 쓴다 — 미검증 파일 목록과 "kkochikkochi 스킬을 실행하라".

## 5. 설치

### 5.1 왜 별도 단계가 필요한가

측정으로 확인한 사실:

```
훅 설치 후 git status   → 아무것도 없음     (git 이 추적하지 않음)
git ls-files            → 훅 없음           (커밋에 포함 불가)
git clone               → 훅 안 따라감      (클론한 쪽엔 게이트 없음)
git worktree            → 훅 공유함         (추가 처리 불필요)
```

`/plugin install`은 `~/.claude/plugins/` 아래에만 파일을 놓는다. 저장소의 `.git/hooks/`에는 닿을 수 없다. 그래서 저장소마다 한 번의 설치가 필요하고, **잊으면 게이트가 조용히 없다.**

### 5.2 조용한 부재를 시끄러운 안내로 바꾸기

Claude 훅이 이 문제를 맡는다. 전역이라 설치가 필요 없고, 하는 일은 파일 존재 확인이라 파싱 정확도와 무관하다.

### 5.3 에이전트 자율 설치

안내는 사람이 아니라 **에이전트에게** 한다. deny 사유에 그대로 실행 가능한 명령을 담아, 사용자 개입 없이 설치되고 커밋이 이어지게 한다.

자율과 확인의 경계는 **변경이 추적되는가**로 가른다.

| 상황 | 실효 훅 디렉터리 | 변경 성격 | 처리 |
|---|---|---|---|
| 훅 없음 | `.git/hooks/` | 미추적 · 로컬 · 되돌릴 수 있음 | **에이전트가 바로 설치** |
| 기존 훅 있음 | `.git/hooks/` | 미추적 · 로컬 · 되돌릴 수 있음 | **에이전트가 체이닝 설치**, 무엇을 옮겼는지 보고 |
| `core.hooksPath` 설정됨 | 예: `.husky/` | **저장소에 추적됨** | **사용자에게 확인 후 진행** |

세 번째가 갈리는 이유: `core.hooksPath`가 있으면 `.git/hooks/`는 완전히 무시되고(측정 확인), 실효 디렉터리는 husky의 `.husky/`처럼 저장소에 커밋되는 디렉터리다. 거기에 파일을 쓰면 `git status`에 뜨고 커밋에 섞일 수 있다. 남의 저장소에 추적되는 변경을 말없이 만드는 것은 자율의 범위 밖이다.

실효 디렉터리는 `git rev-parse --git-path hooks`로 얻는다 — `core.hooksPath` 설정 여부와 무관하게 올바른 경로를 준다.

### 5.4 체이닝

기존 `pre-commit`이 우리 것이 아니면:

1. `pre-commit` → `pre-commit.kkochikkochi-chained` 로 이동
2. 우리 훅을 `pre-commit` 으로 설치
3. 우리 훅은 시작할 때 체이닝된 훅이 있으면 **먼저** 실행하고, 0이 아니면 그 종료 코드로 즉시 끝낸다

**순서의 근거** — 기존 훅(린트, 포맷, 테스트)이 거부하는 코드에 이해도 퀴즈를 내는 것은 순서가 틀렸다. 어차피 커밋되지 않을 코드다.

제거(`/kk-uninstall`)는 이 과정을 정확히 되돌린다. 우리 훅을 지우고 체이닝된 훅을 원래 이름으로 복구한다.

멱등성: 이미 우리 훅이 설치돼 있으면 재설치는 무해해야 하며, 체이닝 파일을 덮어써서 사용자의 원래 훅을 잃어서는 안 된다.

## 6. `--no-verify`

`--no-verify`는 git 훅을 건너뛴다(측정 확인). Claude 훅이 명령 문자열에서 이를 감지해 deny한다.

여기서는 부정확해도 안전하다. 오탐이면 사용자가 질문을 한 번 더 받을 뿐이고, 미탐이면 v1과 같은 상태로 돌아갈 뿐 새로 나빠지지 않는다. **단순 문자열 포함 검사로 충분하며, 토크나이저를 다시 들이지 않는다.**

## 7. 유효한 v1 결정

다음은 그대로 유지된다: 통과 토큰의 blob SHA 바인딩(D08), HEAD 무효화 안 함(D09), `covered.tsv` + `passes/` 분리(D11), 문항 예산과 축(D02·D17·D19·D20), 근거 없는 문항 폐기(D14), 신뢰 경계(D10), 하드 게이트(D01), 오답 루프와 탈출구(D03·D06).

`record-pass.sh`는 명령 문자열 인자를 잃고 `git diff --cached`만 쓴다. 저장 형식과 검증 규칙은 그대로다.

## 8. v2에서 남는 한계

- **`--no-verify`** — Claude 훅이 놓치면 우회된다
- **훅 미설치 상태에서 Claude 훅도 놓치면** 게이트가 없다. v1과 같은 노출이며, 새로 나빠지지 않는다
- **`core.hooksPath` 저장소** — 사용자가 확인을 거부하면 게이트가 없다. 문서에 명시한다
- **`git clone` 후 미설치** — 첫 커밋 시도에서 Claude 훅이 안내한다
