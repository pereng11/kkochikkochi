# 질문 제시 — Claude Code

객관식과 짧은 답은 `AskUserQuestion` 으로 낸다. 선택지 목록에는 항상 **"모르겠다"** 를
하나의 옵션으로 넣는다 (의미와 채점 방식은 `SKILL.md` §2 참조).

## 한글은 리터럴로 쓴다

도구 인자에 한글을 `\uXXXX` 이스케이프로 적지 않는다. 한글은 음절 하나가 코드포인트 하나라, 손으로 고르다 하나만 빗나가도 다른 낱말이 된다. 그리고 **쓰는 동안에는 그 잘못이 보이지 않는다** — 이스케이프 상태로는 자기 문장을 읽을 수 없기 때문이다.

실측한 사례다. 왼쪽이 의도한 낱말, 오른쪽이 실제로 화면에 뜬 것이다.

```
바뀐 문서  →  바뀌 문서     뀐 을 뀌 로
멀쩡한     →  멀짎ka한      쩡 을 짎 로 쓰고 ka 가 섞였다
바뀐다     →  바뀜다        뀐 을 뀜 로
위아래로   →  위리로        아래 가 빠졌다
없앤다     →  없앱는        앤다 를 앱는 로
```

사용자는 "문항이 제대로 보이지 않아서 문제를 풀 수 없음"이라고 답했다. 문항 내용이 아무리 좋아도 이 지점에서 게이트는 이해를 검증하지 못한다.

## 문항 본문은 `preview` 에 넣는다

`AskUserQuestion` 의 `question` 과 `label` 은 터미널 폭에 맞춰 잘린다. 이 도구의
문항은 코드를 인용해야 해서 대개 그 폭을 넘고, 잘리면 **사용자가 문제를 읽지 못해
답할 수 없다** — 게이트가 이해를 검증하는 대신 그냥 막아 세운 꼴이 된다. 실측했다:
긴 라벨과 설명을 단 3문항을 한 번에 냈더니 "문항이 제대로 보이지 않아서 문제를 풀
수 없음"으로 돌아왔고, 아래 배치로 바꾸자 정상적으로 읽히고 답이 돌아왔다.

- **한 번에 1문항.** 여러 문항을 묶으면 각 문항에 돌아가는 화면이 그만큼 좁아진다.
  `SKILL.md` §4 의 오답 재출제 루프도 문항 단위라 어차피 한 번에 하나가 맞다
- **`question` 은 식별표로만 쓴다.** `Q1. 돌연변이 테스트 (preview 참조)` 정도
- **`label` 은 짧은 구.** 선택지를 구분할 최소한의 말만 — 근거와 코드는 `preview` 로
- **`preview` 에 문항 전문 + 근거 코드를 담는다.** 모노스페이스 박스라 들여쓰기가
  보존되고, 폭도 넓다
- **`multiSelect` 는 `false`.** `preview` 는 단일 선택 문항에서만 렌더된다

### 문항 전문은 모든 선택지의 `preview` 에 반복해 넣는다

`preview` 는 **지금 커서가 놓인 선택지의 것 하나만** 보인다. 문항을 한 선택지에만
넣으면 사용자가 다른 선택지로 옮기는 순간 문제가 화면에서 사라진다. 그래서 모든
선택지의 `preview` 가 같은 문항 전문으로 시작하고, 그 아래에 **그 선택지에 해당하는
근거**가 붙는다.

```
【문항】            ← 모든 선택지에서 동일
  ...상황과 질문...
【코드】            ← 모든 선택지에서 동일 (문항이 인용하는 코드)
  cmd_status() { ... }
【이 선택지】        ← 선택지마다 다르다
  cmp -s "$SRC" "$1"  → $SRC 를 못 읽어 실패 → exit 3
```

선택지별 부분은 **정답을 알려주는 자리가 아니다** (`SKILL.md` §6). 그 선택지가
가리키는 코드가 실제로 무엇을 하는지만 보여주고, 판단은 사용자에게 남긴다.
