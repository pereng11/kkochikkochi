# 질문 제시 — Claude Code

객관식과 짧은 답은 `AskUserQuestion` 으로 낸다. 선택지 목록에는 항상 **"모르겠다"** 를
하나의 옵션으로 넣는다 (의미와 채점 방식은 `SKILL.md` §2 참조).

## 배치

`question` 과 `label` 은 터미널 폭에 맞춰 잘린다. 코드를 인용하는 문항은 대개 그 폭을
넘고, 잘리면 사용자가 문제를 읽지 못한 채 막힌다.

- **한 번에 1문항.** 묶을수록 각 문항에 돌아가는 화면이 좁아진다
- **`question` 은 식별표로만.** `Q1. 돌연변이 테스트 (preview 참조)` 정도
- **`label` 은 짧은 구.** 근거와 코드는 `preview` 로
- **`multiSelect` 는 `false`.** `preview` 는 단일 선택 문항에서만 렌더된다
- **문항 본문은 모든 선택지의 `preview` 에 반복해 넣는다.** `preview` 는 커서가 놓인
  선택지의 것 하나만 보이므로, 한 곳에만 넣으면 보기를 옮기는 순간 문제가 사라진다

```
【문항】            ← 모든 선택지에서 동일
  ...상황과 질문...
【코드】            ← 모든 선택지에서 동일 (바꾸기 전과 바꾼 뒤를 나란히)
  바꾸기 전  is_current "$TARGET" && exit 0 || exit 3
  바꾼 뒤    [ -r "$SRC" ] || exit 0
             is_current "$TARGET" && exit 0 || exit 3
【이 선택지】        ← 선택지마다 다르다
  cmp -s "$SRC" "$1"   is_current 의 마지막 검사
```

【이 선택지】 에는 **가리키는 코드와 그 코드가 놓인 위치까지만** 적는다. 그 코드가 무엇을
낳는지(`→ exit 3`)를 적으면 정답 선택지에서는 그것이 곧 답이라, 사용자는 대조만 하면
된다. 물음표도 【문항】 에만 둔다 — 오답 쪽에만 "그렇다면 ~이지 않을까?" 가 붙으면
코드를 읽지 않고 그것만 지워도 정답에 닿는다.

## 한글은 리터럴로 쓴다

도구 인자의 한글은 리터럴 문자로 쓴다. `\uXXXX` 이스케이프는 음절 하나가 코드포인트
하나라 손으로 고르면 빗나가고, 그 상태에서는 자기 문장을 읽을 수 없어 잘못이 눈에
띄지 않는다. 실제로 "바뀐"이 "바뀌"로, "멀쩡한"이 "멀짎ka한"으로 나갔다.
